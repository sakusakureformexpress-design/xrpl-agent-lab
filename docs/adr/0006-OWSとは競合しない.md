# 0006 — Open Wallet Standard と競合せず、その上に乗る

状態: 有効
日付: 2026-09-19

## 背景

2026-09-17、Ripple が Starter Kit v1.1 で **Open Wallet Standard (OWS)** に
XRPL を公式統合した。OWS は MoonPay 主導、PayPal・Circle・Solana Foundation が貢献者。

OWS の公式記述:

> エージェントが秘密鍵にアクセスせずに取引を要求でき、
> **支出上限や承認済みの支払先といった安全策を強制する**

**言葉の上では、我々の第2段（ブローカー）とほぼ同じ。**

## 決定

1. **第2段では競わない。** 将来的にブローカーを **OWS のポリシーバックエンド**として
   実装し直す方向に倒す
2. **第1段（Payment Channel の台帳強制）で差別化する。** OWS にこれは無い
3. ピッチでは OWS を**自分から先に出す**

## 理由

MoonPay が主導し、PayPal・Circle・Solana Foundation が乗り、Ripple が公式採用した標準に、
個人が同じものをぶつけて勝つ理由が無い。

一方で**強制の場所が違う**:

| | OWS | Leash 第1段 |
|---|---|---|
| 上限を強制するのは | vault（ソフトウェア） | **台帳** |
| 秘密鍵の所在 | vault が保持 | 人間の手元のみ |
| **署名マシンが侵害されたら** | **鍵がそこにある** | **上限は動かない** |
| 脅威モデルの記載 | 公式文書に無し | 明記済み |

OWS の公式ドキュメントには、**署名マシン自体が侵害された場合の脅威モデルが無い。**
ローカル優先・自己保管は強調されているが、エンドポイント侵害・マルウェア・
サプライチェーン攻撃には触れていない。

**我々が埋めるのは、その触れられていない領域そのもの。**

## 却下した案

| 案 | 却下の理由 |
|---|---|
| OWS を無視して独自のポリシー形式で進める | 標準が普及したときに孤立する。Ripple の "Open Standards, Not an Island" 方針とも逆 |
| OWS より優れていると主張する | **第2段は実際に優れていない。**嘘は審査で崩れる |
| OWS に触れずにピッチする | 「それ OWS でよくない?」で終わる。**曖昧にすると致命傷** |

## 結果

主張が変わった:

> ~~誰もやっていない~~ → **標準が届かない層を埋める**

前者は調べれば嘘だと分かる。後者は具体的で、検証可能。

**訂正:** 「エージェントの支出上限を強制する OSS が存在しない」は**誤り**だった。
OWS が存在する。ただし**オンチェーンで強制するもの**は依然として無いため、
ピッチの統計（"on-chain" 限定）は事実として維持できる。
