# 0006 — Open Wallet Standard と重複させず、組み合わせて使う

状態: 有効
日付: 2026-09-19（2026-09-23 に OWS 仕様書の本文で確認し直した）

## 背景

2026年9月、Ripple の XRPL AI Starter Kit v1.1 が **Open Wallet Standard (OWS)** に対応した。
OWS は MoonPay 主導・MIT・2026-03-23 公開で、Ripple を含む20以上の組織が貢献している。

報道（CoinDesk 2026-09-17）は OWS を「支出上限や承認済みの支払先といった安全策を強制する」と
説明していた。一方、**OWS 自身の仕様書**はこう書いている:

> "Per-transaction value caps, recipient allowlists, and cumulative daily spend are **not**
> implemented as declarative rules; use an **`executable`** policy (see below) if you need
> that level of control." — `docs/03-policy-engine.md`

> "Compromised process memory — Not fully mitigated in the current in-process model;
> a future subprocess enclave would address this" — `docs/05-key-isolation.md`

> "The agent and signer share an address space." — 同上

**報道より仕様書を正とする。** OWS は署名の前にポリシーを評価する仕組みを持つが、
金額上限・支払先の許可リスト・日次上限は組み込みのルールではなく、
使うなら開発者が実行ファイル（executable policy）を書き、それは署名ホスト上で動く。

## 決定

1. **第2段（ブローカーの判定）を OWS と重複させない。** ブローカーの判定関数は純粋関数なので、
   OWS の executable policy（`PolicyContext` を JSON で受け取り `PolicyResult` を返す）として
   動く形を目指す（ロードマップ。未実装）
2. **第1段（Payment Channel による台帳での強制）は OWS に無い機能として残す**
3. OWS との関係を説明するときは、仕様書の文言に基づいて書く

## 理由

上限を強制する場所が違う:

| | OWS | Leash 第1段 |
|---|---|---|
| 上限を強制するもの | ホスト上のポリシー（金額上限は独自の executable が必要） | **台帳** |
| 秘密鍵の所在 | ホスト上の vault（`~/.ows/wallets/`、AES-256-GCM） | 人間の手元のみ |
| エージェントが持つもの | API トークン（"serves as both authentication and decryption capability"） | チャネルの署名鍵のみ |
| 署名プロセスが侵害されたとき | 仕様書は "not fully mitigated" と記載 | 上限は台帳にあり、動かない |

ホスト上で強制する上限は、プロンプトインジェクションで乗っ取られたエージェントには効くが、
ホストそのものを掌握した者には効かない。台帳の検証ルールは、ホストの外にある。

`effects`（取引による資産移動の解析結果）は、フロー解析を実装していないチェーンでは空になる
（仕様書 L260）。XRPL で金額を見る executable policy は `raw_hex` を自分で解析する必要がある。

## 却下した案

| 案 | 却下の理由 |
|---|---|
| OWS を使わず独自のポリシー形式だけで進める | 標準と別の形式を増やすことになる |
| 第2段を OWS より優れたものとして扱う | 事実ではない。第2段はどちらもホスト上のソフトウェアによる強制 |
| OWS に触れずに説明する | 利用者が比較したい相手に触れないのは不誠実 |

## 訂正の記録

| 以前の記述 | 訂正 |
|---|---|
| 「支出上限を強制する OSS は存在しない」 | 誤り。OWS がある。ただし台帳で強制するものは確認した範囲では無い |
| 「OWS は支出上限と許可リストを強制する」 | 仕様書では組み込みのルールではない（上記） |
| 「OWS には脅威モデルの記載が無い」 | 誤り。`05-key-isolation.md` に脅威モデル表がある |
| 「ポリシーと鍵は同一プロセス」 | 正確には同一マシン。署名コアはエージェントと同一アドレス空間 |
