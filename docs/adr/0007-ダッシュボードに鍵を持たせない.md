# 0007 — ダッシュボードを読み取り専用にする

状態: 有効
日付: 2026-09-19

## 背景

枠の状況を1画面で見たい。素直に作ると「枠を閉じるボタン」を置きたくなる。

## 決定

ダッシュボードは**読み取り専用**にする。

- 起動に要るのは**公開アドレスとポリシーのパスだけ**。シードを読まない
- **`GET` 以外は 405。** 書き込む口が存在しない
- 枠を閉じる操作（`revoke`）は CLI に残す。画面には**実行すべきコマンドを表示するだけ**
- `127.0.0.1` にのみ bind する
- **`Host` ヘッダを検証する**

## 理由

`revoke` には口座の鍵が要る。**ボタンを置くには、常駐プロセスに鍵を持たせることになる。**
そのプロセスは HTTP を喋っていて、認証を持たない。ここに鍵を置くのは、
このプロジェクトが主張していること全部と矛盾する。

`Host` 検証について: 認証の無い localhost サーバは **DNS リバインディング**で読める。
攻撃者が自分のドメインを `127.0.0.1` に解決させ、利用者にそのページを開かせると、
ブラウザは同一オリジンとして API を叩ける。ただし `Host` ヘッダは攻撃者のドメインのままなので、
`localhost` / `127.0.0.1` / `[::1]` 以外を 403 にすれば防げる。

## 却下した案

| 案 | 却下の理由 |
|---|---|
| revoke ボタンを置く | 常駐プロセスに口座の鍵が要る。**主張と矛盾する** |
| 署名だけ持たせて revoke する | `tfClose` を送金元として出すには送金元口座の権限（マスターキー／レギュラーキー／マルチシグ／XLS-75 の委譲）が要る。しかも送金元の `tfClose` は即時に閉じず、`SettleDelay` 後に閉じる予約になるだけ（`research/2026-09-21-xls75-permission-delegation.md` §4.2）。ボタンを置いても停止スイッチにはならない |
| ブラウザ拡張で鍵を扱う | 攻撃面が増える。そもそも CLI で足りる |
| `0.0.0.0` に bind して他端末から見る | 認証が無い。外に出した瞬間に誰でも残高を読める |
| 他人の Memo も表示する | 台帳の Memo 欄は誰でも書ける。**画面に出す理由が無い。**自分たちの `MemoType` のものだけ構造化して出す |

## 結果

- この画面を経由して資金が動く経路が**存在しない**
- 代償: 枠を閉じるには端末に戻る必要がある。**その不便は意図的なもの**
