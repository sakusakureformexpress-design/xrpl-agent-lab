# 0004 — エージェントに口座を持たせない

状態: 有効
日付: 2026-09-18

## 背景

エージェントが支払うには署名が要る。素直に実装すると、エージェントに
ウォレット（＝口座の鍵）を持たせることになる。

## 決定

エージェントは **`privateKey` / `publicKey` のペアだけ**を持つ。
口座（`address`）を持たない。

`LeashAgent` クラスに `address` プロパティは存在しない。
できるのは `signPaymentChannelClaim` による**クレームへの署名だけ**。

## 理由

口座の鍵を渡すと、乗っ取られた時点で**残高の全部**が動かせる。
チャネルの署名鍵しか無ければ、動かせるのは**そのチャネルの残枠だけ**。

被害の上限が、渡した枠の大きさで決まる。これは設計で決められる値になる。

## 却下した案

| 案 | 却下の理由 |
|---|---|
| エージェント専用の口座を作り、少額だけ入れる | 「少額だけ入れる」を守るのは人間の運用。忘れたら終わる。台帳は何も保証しない |
| `DelegateSet` で権限だけ委譲する | ADR 0001 の通り、金額を縛れない |
| HSM / セキュアエンクレーブに鍵を置く | 鍵は守れるが、**署名の要求は通る。**上限の問題は解けない（OWS と同じ限界。ADR 0006） |

## 結果

- エージェントが乗っ取られても、口座は操作できない
- 代償: エージェントは**枠のある相手にしか払えない**（ADR 0003 の第2段が必要な理由）
