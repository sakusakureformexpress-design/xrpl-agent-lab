FINDINGS

調べて分かった、動機づけになる事実

  • XRPL 公式の権限委譲では、金額の上限を付けられない。「granular permission はハードコードで、通貨の限定すらできない」と公式に明記されている。金額を縛れるのは Payment Channel と Escrow だけだった。
  • x402 の XRPL スキームは直接 Payment しか受け付けない。つまり x402 で払うには、エージェントに口座の署名権を渡すしかない。解こうとしている問題が、標準の中に残っている。
  • Hooks は XRPL に存在しない（Xahau の機能）。任意のルールを台帳上で実行させる道は無い。
  • 最有力の競合をソースコードで検証した結果、支払先の許可リストも上限の台帳強制も実装されていなかった（grep で0件）。

LIMITS

正直な限界

  • Payment Channel は XRP 限定。ドル建てのロックは Escrow で可能だが分割払い出しができない。RLUSD が使えないのは技術的制約ではなく発行体がフラグを立てていないため。
  • ブローカーの機械を掌握されると、ブローカー口座の残高までは失われる。ポリシーも状態もその機械の上にあるため書き換えられる。実装では消せない構造的な限界。
  • 市場はまだ小さい。XRPL 上の x402 は毎時3,663件だが1事業者分の数字で、業界全体では約半分が自己取引等の人工的なものと分類されている。
  • チームが弱い。非エンジニア1人＋AIエージェント。XRPL の実装判断ができる人を探している。
