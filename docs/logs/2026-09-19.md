## 設計上の判断

### 鍵を持たせない

起動に要るのは公開アドレスとポリシーのパスだけ。`--address` があればシードは読まない。
枠を閉じる操作（`revoke`）は口座の鍵を要するため、**ダッシュボードには持たせず CLI に残した**。
画面には代わりに実行すべきコマンドを出す。

### 書き込む口を作らない

`GET` 以外は 405。これにより、この画面を経由して資金が動く経路が存在しない。

### `Host` ヘッダの検証

認証を持たない localhost サーバは、DNS リバインディングで外部のページから読める。
攻撃者のドメインを `127.0.0.1` に解決させても `Host` は攻撃者のドメインのままなので、
`localhost` / `127.0.0.1` / `[::1]` 以外を 403 にする。

### 他人のメモを描画しない

台帳の Memo 欄は誰でも書ける。既存の `parseMemo()` は自分たちの `MemoType` のものだけを
返すので、これを使い、それ以外は件数だけ数えて中身は出さない。
自分たちのメモに入る `invoice` / `resource` も相手のサーバ由来なので `textContent` 限定。

### 台帳強制とソフト強制を合算しない

ヒーローの数値は「いまエージェント側が動かせる上限の合計」。
内訳として**台帳が強制している分**と**ブローカー口座の残高（ソフトが強制）**を必ず分けて出す。
侵害されたときの挙動が違うため、合計だけを見せると誤解を招く。

### 両方の口座の履歴を見る

第1段の記録は所有者の口座に、第2段の記録はブローカー口座に残る。
片方だけを見ると記録が片肺になるため、両方から取って重複を除き、新しい順に並べる。

## 見た目の検証

Chromium で light / dark / 390px の3通りを描画して確認した。

- 深刻度タグが「色玉＋記号」で二重になっていたのを、**色つきの記号ひとつ＋ラベル**に直した
- 記号は深刻度ごとに形を変えた（`●` / `▲` / `■` / `—`）。色だけで区別させないため
- 狭い画面で記録の表が1文字幅まで潰れていたので、表に最低幅を与えて横スクロールに逃がした
- `tecUNFUNDED_PAYMENT` が単語の途中で折れていたので、結果の列に最低幅を与えた

パレットは status パレットを使用。検証スクリプトでは
`good` と `critical` の CVD 分離が 4.1 で FAIL するが、これは status パレットの既知の性質であり、
**記号＋ラベルを必ず添える**ことが規定の対処。`warning` は明るい面に対して 1.83 で
コントラスト警告が出るため、**数値を必ず文字で併記**している。どちらも満たしている。
