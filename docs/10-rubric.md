# 10 — 採点表（Judge 用）

最終更新: 2026-09-18
根拠: XRPL Grants の公開評価軸 https://xrplgrants.org/ / https://xrplgrants.org/faq

合格閾値: **70 / 100**

## 配点

| # | 項目 | 配点 | 判定基準 |
|---|---|---|---|
| 1 | **XRPL 必然性** | 20 | Escrow / Payment Channel / Credentials(XLS-70) / Permissioned Domains(XLS-80) / 組み込みDEX・AMM / MPT / マルチシグ 等の固有機能に依存しているか。単なる送金なら 0〜5 |
| 2 | **課題の実在性** | 15 | 「無いと困っている人」が具体的に存在し、その証拠があるか |
| 3 | **成長指標の設計** | 15 | オンチェーンで測定可能な成功指標が定義され、それが伸びる仕掛けがあるか（助成金の70%がここに紐づく） |
| 4 | **技術的健全性** | 15 | アーキテクチャ、エラー処理、鍵管理、テスト、再現性 |
| 5 | **動く実物** | 15 | PoC/MVP が実在し第三者が再現可能か。tx hash 等の証拠 |
| 6 | **チームと実行力** | 10 | 完遂実績、コミット履歴、技術的裏付け |
| 7 | **提出物の完成度** | 10 | 2分デモ動画 / ピッチデック / README が**英語で**成立しているか |

## 減点

| 事象 | 減点 |
|---|---|
| 他チェーンでもそのまま成立する設計 | −20 |
| 動くものが無く構想のみ | −15 |
| 出典・証拠のない主張が申請物に含まれる | −10 |
| 成功指標が測定不能な記述 | −10 |
| 未実装機能を実装済みのように記述 | −15 |

## スコアの読み方

| 点数 | 扱い |
|---|---|
| 85+ | 申請可。面接準備へ |
| 70〜84 | 申請可だが top_3_gaps を潰してから |
| 50〜69 | 差し戻し。同じ企画で改善可能 |
| 〜49 | **企画ごと捨てる。** 改善ではなく作り直し |
